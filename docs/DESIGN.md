# 設計（自転車ルートロガー 0.11.0）

## 1. 画面と流れ

```
ホーム ─┬─［フリーサイクリング］────────────→ 走行画面（フリー）
        ├─［ルートサイクリング］→ プランを選ぶ → 走行画面（ルート）
        ├─ ルートプラン（一覧 → 編集）
        ├─ 記録（一覧 → 詳細 / 一覧の上の［まとめ］→ 全記録のまとめ / 右上の取り込み → ファイルから記録を取り込む（0.10.0）/
        │        ［絞り込み］→ 条件 →（場所）地図で範囲を選ぶ・［この条件でまとめを見る］→ 絞り込んだまとめ（0.11.0））
        └─ 設定
```

- 初回は「安全のために」（走行中に操作しない・ホルダーに固定）に同意するまで先へ進めない。設定から再表示できる。
- 起動時に「記録の途中で終わっています」（status が FINISHED でない記録がある）→［続ける］/［終了して保存］。
- 走行中のモードとプラン（`SettingsStore.ride`）と目的地（`SettingsStore.destination`）は SharedPreferences に保存し、
  アプリを閉じても保つ。記録中はモードを切り替えられない。

### 走行画面（`ui/RideScreen.kt`）

- 地図: 4 種類（標準 / 航空写真 / 航空写真＋地名 / 地形。保存）、現在地（`LocationHub` を `LocationSource` として渡すので
  記録と同じ位置。青点・精度円・向きは SDK の現在地レイヤー）、追従（しない → 北が上 → 進行方向が上 のボタンで巡回。保存。
  手で動かすと「しない」に）、ズーム ±、縮尺（maps-compose-widgets の ScaleBar）、プラン全体に合わせる。
- 上: 目的地パネル（矢印・「北東 1.2 km」・ルート沿いの残り・解除）、ルートの案内パネル（外れ距離・始点から・残り・
  次の経由地と名前・種類・ルート沿いの残り）。
- 下: 記録パネル（速度・距離・走行時間・全体時間・獲得標高・平均・最高・状態、一時停止/再開・終了・大きな表示）。
- 大きな表示: 地図を隠して数字を大きく（速度 96sp など）。戻るキーで地図へ。
- 地図の長押し →［ここへ向かう］/（ルートモード）［経由地として登録して向かう］。経由地のタップ →［ここへ向かう］/［編集］。
  一覧ボタン → ルート沿いの順の経由地から目的地を選ぶ。
- 目的地が画面外なら、画面の端（右のボタン列と上下のパネルを除いた範囲）に方向の矢印と距離（`Bearing.edgeMarker`）。
- 記録中かつ設定 ON なら画面を点けたまま（`view.keepScreenOn`）。

### プラン編集（`ui/PlanEditScreen.kt`）

- 地図（ルートの線・始点 S / 終点 G・経由地。経由地はドラッグで移動・タップで編集/削除、長押しまたは［＋］（地図の中心）で追加）。
  **地図の大きさ**（0.2.0）: 既定は画面の 60%。地図と一覧の境目の**つまみ**をドラッグで 30〜85%（`Settings.planMapRatio`、離したときに保存）。
  横長の画面では地図が左・一覧が右（同じ割合を幅に使う）。地図の右上の［全画面］で地図だけにし、ルート・経由地の一覧は
  下から引き出すシート（`BottomSheetScaffold`。経由地をタップすると地図がそこへ動きシートは下がる）。戻るキーで元に戻る。
  全画面でも長押しで追加・ドラッグ・タップで編集ができる。
- 合計（距離・獲得標高・ルート数・経由地数）と、経由地の種類のフィルタ（右端のボタンのメニュー。地図と一覧から隠す。保存）。
- タブ: ルート（色・表示/非表示・上下で並べ替え・名前変更・地図に合わせる・削除・タップで標高グラフ）/
  経由地（ルート沿いの順。始点から何 km、1 km 超離れていれば「ルートから ○ 離れています」。**タップで地図をその経由地へ**、鉛筆で編集）/ メモ。
- 読み込み（右上のファイルのボタン）: ［ファイルから］（SAF）/［QR コードから］/［URL から］（§3.1）。
- メニュー: URL から再読み込み（URL から取り込んだものがあるとき）・GPX で書き出す（SAF）・共有（FileProvider）・複製・削除。

## 3. GPX

- 読み込み（`gpx/GpxParser.kt`）: XmlPullParser のストリーミング。名前空間は見ない（1.0 / 1.1 / 接頭辞つき）。
  `trk` と `rte` は 1 本ずつ別のルートになる（trkseg は区間）。`wpt` は経由地（`<type>` → `<sym>` → `<name>` の順で種類を推定）。
  `extensions` は読み飛ばす。上限: 64 MB・20 万点（超えたら 1 つおきに間引いて以後も同じ間隔。各区間の始点・終点は残す）・
  経由地 2,000。途中で壊れていれば読めたところまで（メッセージで知らせる）。XML でない/中身が無いはエラー。
- 書き出し（`gpx/GpxWriter.kt`）: GPX 1.1。記録 = 1 本の trk（区間 = 一時停止の切れ目）。プラン = ルートごとに trk、
  経由地は wpt（`<name>` `<desc>`=メモ `<time>`=予定時刻 `<sym>` `<type>`=種類 code）。読み戻すと同じになる（単体テスト）。
- 受け取り: SAF（複数選択、`application/gpx+xml` ほか `*/*`）、他アプリの「開く」（GPX の MIME、または拡張子 .gpx）・「共有」、
  QR コード・URL（§3.1）。プラン編集から以外は「どのプランに入れるか / 新しいプラン」を聞く。

### 3.1 URL・QR コードからの読み込み（0.2.0、`net/`）

- **通信するのは利用者が指定した URL（QR を含む）とそのリダイレクト先だけ**（GPX の取り込みについて。ほかの通信は §10 更新の確認・§4.6 場所名の検索）。HttpURLConnection（Maps 以外に通信ライブラリは無い）。
  User-Agent `CycleRouteLogger/<版> (Android)`。Cookie・認証は送らない。
- **https のみ**（http は拒否）。リダイレクトは自分でたどり **https 同士で最大 5 回**（http への転送・6 回目で中止）。
  `accounts.google.com` への転送は「ログインが必要」＝ Drive なら共有設定の案内。接続 15 秒・読み込み 30 秒でタイムアウト。
- **大きさの上限はダウンロード 20 MB**（`RemoteGpxFetcher.MAX_DOWNLOAD_BYTES`）。ファイルの 64 MB より小さくしたのは、モバイル回線で長く待たせない・
  全体をメモリに持つため（1 秒ごとの 20 万点でも GPX は 20 MB 前後）。Content-Length で先に断り、読みながらも数える。
  gzip（先頭 1F 8B）は展開して読み、展開後は GPX の解析の上限（64 MB・20 万点）が効く。
- URL の書き換え（`RemoteUrls`、単体テストあり）:
  - Google ドライブ: `drive.google.com/file/d/<ID>/…`（`/file/u/N/d/` も）・`/open?id=`・`/uc?id=`（docs.google.com/uc も）・
    `drive.usercontent.google.com/download?id=` → `https://drive.usercontent.google.com/download?id=<ID>&export=download`（resourcekey は引き継ぐ）。
    フォルダ（`/drive/folders/`）・Google ドキュメント等は非対応と案内。大きいファイルの「ウイルス スキャンを実行できません」の HTML は
    `<form id="download-form">` の hidden（id / export / confirm / uuid）か、古い形の `confirm=` のリンクを読んで本体を取り直す（2 回まで）。
    それ以外の HTML（ログイン画面・アクセス権が必要）・401/403 は「共有設定を『リンクを知っている全員』に」。ダウンロード上限の HTML / 429 は「しばらく待つ」。
  - Dropbox: `dl=0` → `dl=1`（無ければ足す、rlkey などは残す）。フォルダ（`/scl/fo/`・`/sh/`）は非対応。
  - OneDrive: `onedrive.live.com/redir|embed` → `/download`、SharePoint は `download=1`、`1drv.ms` などは共有 API
    （`api.onedrive.com/v1.0/shares/u!<base64url>/root/content`）。HTML・401/403/404 なら「この OneDrive のリンクからは取得できない」と案内
    （**実際の OneDrive のリンクでは未確認**。Microsoft 側の仕様で匿名の取得が通らないことがある）。
  - GitHub: `github.com/<o>/<r>/blob/<ref>/<path>` → `raw.githubusercontent.com/…`、gist → `gist.githubusercontent.com/<u>/<id>/raw`、`/tree/` は非対応。
  - それ以外の https はそのまま（日本語などは % にして取りに行く）。文の中に URL があれば取り出し、スキームが無ければ https を補う。
- 中身の判定（`RemoteContent.classify`）: 先頭 8 KB の最初の要素が `gpx`（接頭辞つきも）なら GPX、`html` / `<!DOCTYPE html` なら HTML
  （「ダウンロードできるリンクではありません」）、それ以外の XML・テキストは「GPX ではありません」。UTF-16 の BOM も見る。
- ファイル名: Content-Disposition（`filename*` 優先）→ URL の最後のパス（拡張子つき）→ GPX の name → `route.gpx`。
- 流れ: 取得中ダイアログ（進み具合・［キャンセル］で接続を切る）→ **確認画面**（ルート名・本数・距離・点数・経由地の数・元の URL、［取り込む］［やめる］）
  → プラン一覧からならファイルと同じ「どのプランに入れるか」、プラン編集からならそのプランへ。
- **再読み込み**: 取り込んだルート・経由地に `sourceUrl`（利用者が渡した URL）を保存し、プランのメニュー［URL から再読み込み］で取り直して、
  その URL から取り込んだものだけを置き換える（ルートの色・表示・並び位置は順に引き継ぐ。手で足した経由地や他のルートはそのまま。
  消えた経由地を目的地にしていたら地点だけの目的地にする）。バックアップの manifest にも sourceUrl を入れる。
- **QR コード**: Google Code Scanner（`play-services-code-scanner`、`GmsBarcodeScanning`）。読み取りの画面は Play 開発者サービスが出すので
  **アプリに CAMERA 権限は無い**。Manifest の `com.google.mlkit.vision.DEPENDENCIES = barcode_ui`（Play からのインストール時に入る）、
  入っていなければ `ModuleInstallClient` でダウンロードしてから始める。Play 開発者サービスが無い・入れられないときは
  「使えません」→［URL を貼り付ける］。中身が URL なら取得、GPX の XML そのもの（短い GPX）ならそのまま確認画面、どちらでもなければ中身を見せて案内。
  エミュレータ（Google APIs イメージ・GMS 24.23・Play ストア無し）ではモジュールをダウンロードできず「使えません」の案内になることを確認（実機で要確認）。

## 4. 記録（`record/`）

- `RecordingService`: フォアグラウンドサービス（type=location）。**記録の点を取り込む（`session.onLocation`）のはこのサービスだけ**で、
  LocationHub を owner "record" で持つ（走行画面の owner "ui" は画面が見えている間の表示用。画面を離れても記録には影響しない）。
  前面の走行画面から開始するので「使用中のみ」の許可で、画面オフ・ホームで裏・他のアプリを開いても位置が届く。WAKE_LOCK（上限 24 時間）。
  通知に全体/走行時間と距離（5 秒ごと）、一時停止/再開ボタン。
- **開始の確認**（0.2.0、走行画面）: 正確な位置 → 通知（Android 13+。未許可なら「許可しなくても記録はできるが、記録中か分かりにくく止められやすい」と
  説明して［許可する］/［通知なしで始める］）→ 初回だけ電池の最適化の案内（［設定する］で記録を始めてから `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`、
  ［あとで］）。押し付けない（2 回目からは出さない。設定画面からいつでも）。
- **開始に失敗したら黙らない**: `MainViewModel.startServiceAndWait` が `startForegroundService` の例外と、サービス側の `startForeground` の失敗
  （`RecorderStatus.startFailure`: SecurityException = 位置の権限、ForegroundServiceStartNotAllowedException = 前面でない、4 秒たっても始まらない = 電池の制限など）
  を待ち、失敗なら空の記録を消してダイアログで理由と対処（アプリの設定・電池の設定を開く）を出す。
- 記録中は走行画面の記録パネルの上に「バックグラウンドでも記録中」（サービスが動いている＝ `RecorderStatus.serviceRunning`）。止まっていれば赤字と［再開］。
- **端末の状態の変化**: 位置情報が OFF（`LocationManagerCompat.isLocationEnabled`、onProviderEnabled/Disabled と 5 秒ごと）・
  使える位置（精度 30 m 以内）が 60 秒届かない → 通知（「記録の注意」チャンネル、音あり 1 回）と記録の出来事（`track_event`）に残し、画面にも赤字。
  LocationHub は無効なプロバイダにも登録してあるので、ON に戻れば自動で続きが記録される（区間は切らない）。
- **プロセスごと落とされたとき**（START_STICKY で intent = null の再起動）: 位置が「常に許可」（ACCESS_BACKGROUND_LOCATION。設定画面から任意で案内、
  必須にしない）なら location 型で始め直し、`resumeUnfinished` で続きを記録（出来事 restarted）。「使用中のみ」・始められないときは
  「記録が止まりました。開いて続ける」の通知を出して止める → 開くと「記録の途中で終わっています」→［続ける］（出来事 interrupted）。
  Android 12+ は裏からのフォアグラウンドサービス開始に制限があり、電池の最適化の対象外だと通りやすい。
- `RecordingSession`: 採用した点を 1 本の書き込みキュー（Channel）で順番に Room へ。統計は 10 点ごと・一時停止・終了で保存。
  終了時に点が 0 なら記録ごと消す。
- `RideTracker`（純ロジック）:
  - 捨てる点: 精度 30 m 超、時刻が戻った点、前の点から 100 km/h 超の跳び（5 回続いたら外れ値は前の点の方とみなし、そこから測り直す＝区間を切る）。
  - 速さ: 端末の速度（ドップラー）、無ければ 5 秒前の点からの移動÷時間。端末の速度が 0 でも位置で 7.2 km/h 以上なら位置を信じる。直近 3 回の中央値。
  - 距離: 採用点から 3 m 以上動いたら足す。
  - 自動一時停止（設定 ON/OFF）: 3 km/h 未満が 5 秒続いたら、止まり始めからの時間と距離を数えない。動き出したら止まった地点からの距離を足す。
  - 獲得標高（記録中の表示）: 0.9.0〜 `ElevationGain.Live`（§4.9。0.8.0 までは GPS 高度を EMA（α=0.3）で平滑化して直近の底から 4 m 以上の登りを足していた）。
    記録を終えたら `ElevationGain.of`（前後の窓）で数え直して保存する。
  - 手動の一時停止 → 再開で区間を切る（間の時間・距離は数えない）。
  - 保存した点を同じ順に流し直すと同じ統計になる（`TrackRepository.replay`。途中で落ちた記録の再開・終了で使う）。
- 走行時間 = 数えた時間、全体時間 = 開始から今（記録の詳細では開始から終了）。平均 = 距離 ÷ 走行時間。

## 5. 案内（`guide/Navigator.kt`）

- アプリ全体で 1 つ。`LocationHub.last` と、ルートモードのプラン（表示中のルートを並び順につないだ線）・経由地・目的地・設定から計算する
  （記録中で画面が消えていても動く）。
- 外れ距離・進捗（`RouteMatcher`）: 現在地を原点にした局所平面で全線分への最短距離。進捗は足の位置までの道のり（区間の空白は数えない）。
- **案内に使う位置は測位のまま**（0.9.0 で判断。§4.9）: 外れ距離・進捗・次の経由地・接近・到着・目的地の矢印は `LocationHub.last`（その時の測位。
  Google の融合測位を選んでいればその位置）をそのまま使い、軌跡のなめらかさ（後処理）や記録中の線の前向きフィルタは通さない。遅れを出さないため
  （前向きのフィルタでも曲がった直後に数 m 遅れ、到着 30 m・接近 100 m・外れ 30〜200 m の判定には数 m のギザギザより遅れの方が困る。外れの知らせは 6 割まで戻るまで繰り返さないので揺れで鳴り続けることもない）。
- ルート外れ: 設定の距離（30/50/100/200 m、既定 50）を超えたら知らせ、その 6 割まで戻ったら「戻った」音。
- 次の経由地（`WaypointsOnRoute`）: ルート沿いの順で、今の進捗より先（通り過ぎて 20 m までは同じ）・ルートから 1 km 以内のもの。
- 接近: 経由地まで直線 100 m 以内で 1 回知らせる（設定 ON/OFF）。
- 目的地: 直線距離・方位角（8 方位の名前）。ルートモードで目的地がルートから 200 m 以内なら「ルート沿い」も。
  30 m 以内で到着 → 音と振動・ダイアログ（［次の経由地へ］/［目的地を解除］/［そのまま］）。
  設定「次の経由地を自動で目的地にする」なら、次の経由地が変わるたびに目的地にする（着いた経由地は飛ばす）。
- 矢印の向き: 地図上の矢印 = 方位角 − 地図の回転（`Bearing.screenRotation`）。進行方向が上のときの地図の回転は、動いていれば
  進行方向、止まっていれば端末の向き（`HeadingProvider`: 画面の上方向と背面方向を足した水平成分。寝かせても立てても効く）。
  大きな表示では地図が無いので同じ向きを「上」として描く。

### 4.1 記録 → ルート・GPX（0.2.0、`record/TrackExport.kt`・`ui/TrackExportUi.kt`）

- 入口: **記録を終えたとき**のダイアログ（［ルートとしてプランに保存］［GPX で書き出す］［共有］［あとで］。フリー・ルートどちらでも）、
  記録の一覧の各項目の ︙（長押しでも）、記録の詳細の上部のボタン。
- ルートとして保存: 入れるプラン（既存 / 新しいプラン。既定は記録したプラン）、ルート名（既定は記録名＝日付＋プラン名）、
  点の間引き（Douglas–Peucker、しない / 3 / 5 / 10 m。既定 5 m。区間ごと・始点終点は残す）、止まっていた間の点を除く
  （平滑化した速度 3 km/h 未満。自動一時停止中もこれ。区間の始点終点は残す）。区間（一時停止・跳び・アプリが落ちた切れ目）はルートの区間になる。
  `sourceTrackId` に記録の id。
- GPX で書き出す / 共有: 軌跡を trk 1 本（区間 = trkseg）、ルートサイクリングならプランの経由地のうち軌跡から 100 m 以内を通ったものを
  wpt（種類つき、名前に通った時刻）として入れるか選べる。ファイル名は `yyyy-MM-dd_<名前から日時を除いたもの>.gpx`。
- テスト（`TrackExportTest`）: 間引いても元の全点が許容誤差 + 0.5 m 以内・長さ 2% 以内、止まっていた点の除去、区間分け、
  書き出し → 読み戻しで同じ距離・区間・経由地、通った経由地の判定。

## 4.2 写真（0.3.0、`photo/`・`ui/CameraScreen.kt`・`ui/PhotoUi.kt`）

- 走行画面の右下の大きな［写真］→ アプリ内カメラ（CameraX、背面、TextureView のプレビュー）。1 タップで撮って
  フォトライブラリ（MediaStore、`Pictures/自転車ルートロガー`。Android 10+ は権限不要、9 以下は WRITE_EXTERNAL_STORAGE maxSdk 28）に JPEG で保存し、
  そのまま連写できる。上に「走行中は止まってから撮影」。CAMERA は撮影ボタンを初めて押したときに求める（`uses-feature camera required=false`）。
  左下（Google のロゴ）を避けるため右下に置き、右のボタン列は下を空ける。
- 登録（`PhotoRepository.addCaptured`）: 位置は 30 秒以内・精度 50 m 以内の測位、無ければ記録の軌跡から時刻で補間（`PhotoLocator.interpolate`。
  端から 5 分・空白 10 分を超えたら不明）。EXIF に DateTimeOriginal・OffsetTimeOriginal・SubSec と GPS（度分秒の有理数、`ExifGps`）を書く
  （設定「撮った写真に位置を書き込む」OFF なら GPS を書かない・消す）。縮小版（長辺 320 px）を `files/thumbs/` に。
- 他のアプリで撮った写真: 記録の詳細の［この時間に撮った写真を追加］→ Photo Picker（権限不要、最大 50 枚）。EXIF の撮影日時（オフセットが無ければ端末のタイムゾーン）が
  記録の前後 10 分に入るものだけ。位置は EXIF の GPS、無ければ軌跡から補間（**Photo Picker は GPS の EXIF を消して渡すので、実際はほぼ補間になる**）。
  同じ URI・同じ記録で撮影時刻が ±1 秒の写真は重複として飛ばす（自分で撮った写真を Picker で選び直した場合）。
- 地図: 記録の詳細と走行中の地図に縮小版つきのマーカー → タップで拡大表示（左右に送る、撮影時刻・位置の出どころ）。削除は「アプリから外す」
  （紐づけと縮小版だけ）か、アプリで撮った写真なら「ライブラリからも削除」（Android 11+ は `createDeleteRequest` の確認）。
- GPX 書き出しで「写真の位置も入れる」を選ぶと、wpt（名前 = 「写真 HH:mm」、type = photo）として入る。

## 4.3 SNS 用の画像（0.3.0、`photo/ShareCardLayout.kt`・`ShareCardRenderer.kt`・`ui/ShareCardScreen.kt`）

- 記録の詳細の［SNS 用の画像を作る］。大きさ: 正方形 1080×1080 / 縦 1080×1350 / 横 1200×630。地図: 標準 / 航空写真 / 地形 / 地図を使わない。
  タイトル（編集可）・アプリ名の小さな表記（ON/OFF）・写真 1〜6 枚（タップした順に番号。既定は位置のある写真から 6 枚）。
- レイアウト（`ShareCardLayout.compute`、純ロジック・単体テスト）: 上にタイトルと日付、下に統計（距離・走行時間・平均・獲得標高）とアプリ名、
  間に地図と写真。縦長・正方形は地図の下に写真（3 枚まで 1 段、4〜6 枚は 2 段で下の段は中央寄せ）、横長は地図の右（1 列か 2 列）。
  全サイズ × 0〜6 枚 × アプリ名あり / なしで「はみ出さない・重ならない・地図は画像の 30% 以上・写真のマスは 120 px 以上・番号は読む順」をテスト。
- 地図: 画面の上の地図（Google マップ）を**画像の地図の枠と同じ縦横比**で出し、ルート全体と写真が入るように合わせる（手で動かしてもよい）。
  ［画像を作る］で読み込み完了（`setOnMapLoadedCallback`、5 秒）を待って `GoogleMap.snapshot` → 切り取らずにそのまま縮めて描くので、
  **Google のロゴと著作権表示は画像に残る**。ピンの位置は `projection.toScreenLocation` から。近いピンは横にずらして番号を読めるようにする。
  読み込みが終わらない（キーが通らない等）・「地図を使わない」ときは、白地に方眼と軌跡（緑 = 始点、赤 = 終点）と番号ピンだけの代替表示
  （「地図を読み込めなかったため…」と表示）。
- ［保存］はフォトライブラリ（`Pictures/自転車ルートロガー`、JPEG 92%）、［共有］は cache/share の JPEG を FileProvider で共有シートへ。
  画像が端末の外に出るのは利用者が共有したときだけ。

## 4.5 記録の詳細: 地図の広さ・区間・時速の分布（0.5.0、`ui/TrackScreens.kt`・`ui/TrackAnalysisUi.kt`・`stats/RideAnalysis.kt`）

ユーザー要望（2026-10-12）「記録を見る画面で地図をもっと大きくみられるようにしてください。走行距離 1km ごとの時間・速度 / 走行距離 5km ごとの時間・速度、
時速の分布のヒストグラムがみられるようにしてください。2km/h ごとに bin を設けてください」

- **地図**: ルートプラン（§1）と同じ作り。既定は画面の 60%、境目のつまみで 30〜85%（`Settings.trackMapRatio`、キー `track_map_ratio`。プランとは別に保存）。
  横長は地図が左・情報が右。地図の右上に［全画面］［記録全体を地図に合わせる］、左上に速度の凡例（地図に重ねる）。［全画面］では地図だけにし、
  情報は下から引き出すシート（`BottomSheetScaffold`、引き出すと画面の 70%。戻るキーで元に戻る）。範囲合わせは最初の 1 回と［合わせる］ボタンだけ
  （つまみを動かしても勝手に合わせ直さない）。写真のマーカー・ズーム ± は今までどおり。
- **情報**: タブ「概要」（今までの内容: ［ルートとして保存］［GPX で書き出す］［共有］・写真・SNS 用の画像・統計・出来事・標高）/「区間」/「速度の分布」。
  上部のバーの共有・メニュー（GPX・ルート・名前変更・削除）も残す（全画面のときは概要タブのボタンを使う）。
- **計算の元**（`RideAnalysis.from`、`TrackRepository.analyze`）: 保存した点を記録と同じ順・同じ区間の切れ目で `RideTracker` に流し直し、
  `RideTracker.onCounted` で「走行時間・距離に数えた 1 回分」（`CountedStep`: 時間・距離・その点の平滑化した速さ）を受け取る。
  止まりかけ（3 km/h 未満で自動一時停止になる前）の分は、動き出して数えると決まったときにまとめて渡し、自動一時停止になったら捨てる。
  これで区間・分布の時間の合計 = 記録の走行時間、距離の合計 = 記録の距離にちょうど一致し、跳び・精度の悪い点・自動一時停止の扱いも統計と同じになる。
  Room は変えない（毎回点から計算。数万点でも Default ディスパッチャで一瞬）。
- **区間**（`splits(1000)` / `splits(5000)`）: 走行距離（一時停止で trkseg が分かれても通して数える。一時停止の間に動いた分は数えない）を区切りの長さで切る。
  区切りが 1 回分の途中にあるときは、その 1 回分の時間を距離の割合で前後に分ける（線形補間。1 回分で 2 つ以上またぐこともある）。
  距離の増えない時間（3 m 未満の動き・止まりかけ）はその時点の区間に入る。境目の時刻は丸めてから引くので、区間の時間の合計は走行時間と 1 ms もずれない。
  各行: 区間（0–1 km）・走行時間・平均（区間の距離 ÷ 走行時間）・最高（区間にかかった 1 回分の平滑化した速さの最大）・登り（獲得標高が増えた時点の走行距離の区間。
  ちょうど区切りなら前の区間）。最後の端数（6.37 km なら 6–6.37）は斜体と「端数」。距離がちょうど区切りで終わり時間だけ残ったら最後の区間に足す。
  いちばん速い・遅い区間（平均で比べる。端数の区間は除く。区切りの区間が 2 つ以上のとき）を緑・赤の背景にする。
  **全体時間（止まっていた時間を含む）は区間には出さない**（自動一時停止の止まりかけの扱いで境目があいまいになるため。記録全体の全体時間は概要にある）。
- **時速の分布**（`histogram(2.0)`）: 2 km/h ごとの bin（**下端を含み上端を含まない**。ちょうど 2.0 km/h は 2–4。m/s → km/h の丸め誤差で落ちないよう 1e-9 足して floor）。
  各 1 回分の時間（または距離）を、その点の平滑化した速さ（記録中の表示・最高速度と同じ直近 3 回の中央値）の bin に足す。0 から最高速度を含む bin まで並べる（空の bin も出す）。
  自動一時停止中・手動の一時停止中は入らない。自動一時停止 OFF の記録では止まっていた時間も走行時間なので 0–2 に入る。GPS の跳び（100 km/h 超）は記録と同じく捨てる。
  棒グラフ（Canvas）: 縦軸は分（［距離］に切り替えると km。目盛りは 1・2・5 × 10^n で 4 本まで）、横軸は km/h（重ならない間隔で数字）、平均速度に赤い破線。
  棒をタップすると「12–14 km/h：8分32秒（全体の 18%）」（もう一度で解除）。
- SNS 用の画像には区間・分布は入れていない。
- テスト（`RideAnalysisTest`）: 1 km の境目の補間（600 m + 600 m → 166.667 秒）、1 回分で複数の区切り、ちょうど区切りで終わる・後の時間、端数だけ、最速・最遅（端数を除く）、
  区間の最高、5 km、bin の境界（2.0 → 2–4・1.999 → 0–2・空の bin）、自動一時停止の除外（止まった 60 秒が入らない）、自動一時停止 OFF、
  手動の一時停止で区間が分かれても距離は通す、雑音・跳び・精度の悪い点・一時停止入りの約 6 km で区間（1 km / 5 km）・分布の合計が `replay` の走行時間・距離・獲得標高・最高速度と一致。

## 4.6 場所名で地点を検索（0.6.0、`geo/PlaceSearch.kt`・`ui/PlaceSearchUi.kt`）

ユーザー要望（2026-10-12）「trip planner で実装済みの場所を言葉で検索する機能を追加してください。」→ trip_planner の `data/Nominatim.kt`・`LocationPickerDialog` と同じ作法。

- **検索サービス**: OSM Nominatim（`https://nominatim.openstreetmap.org/search`、API キー不要）。`q`・`format=jsonv2`・`limit=10`・`accept-language=ja`、
  地図の表示範囲を `viewbox`（西,北,東,南。0.1 度単位で外側に丸める）と `bounded=0`（範囲の外も返す。近い結果を優先するだけ）。日付変更線をまたぐ範囲は付けない。
  q は `URLEncoder` で % にし、空白は `%20`（全角空白・続く空白は 1 つに）。
- **差し替え口**: `PlaceSearch`（`query, near → List<PlaceResult>`、`attribution`）。実装は `NominatimSearch` だけで、`CycleApp.placeSearch` で作る。
  Google Places などに替えるときはこれを実装して差し替える（画面は `PlaceResult` と `attribution` しか見ない）。
- **利用ポリシーを守る仕組み**: User-Agent `CycleRouteLogger/<版> (jp.kjtr.cycleroutelogger)`。`RateGate` で同時に 1 つ・**前の検索が終わってから 1 秒あける**
  （失敗した検索も数える）。同じ検索（正規化した語 + 丸めた viewbox = 同じ URL）の結果は LRU で 50 件までメモリに覚え、送り直さない（0 件も覚える。失敗は覚えない。
  プロセスが続く間だけ・保存しない）。**送るのは検索ボタン / IME の検索キーを押したときだけ**（入力中の自動補完はしない）。端末がネットにつながっていなければ送らずに「オフライン」。
- **通信**: HttpURLConnection の GET 1 回（https のみ・リダイレクトはたどらない・接続 10 秒 / 読み込み 15 秒・1 MB まで・`useCaches = false`）。
  429 / 403 →「混み合っています」、名前解決できない → オフライン扱い、タイムアウト・その他の HTTP・読めない応答はそれぞれの文。
- **応答の解析**（`NominatimSearch.parse`）: lat/lon は文字列。name が空なら display_name の先頭（カンマの前）。boundingbox（南,北,西,東）を `bounds` に。
  住所の要約（`addressSummary`）は display_name から名前・郵便番号・番地を除き、日本なら国名を除いて大きい方から（「東京都 千代田区 丸の内」）。
  経由地の種類の推定（`guessType`）は、分類が POI（amenity / shop / tourism / railway / leisure / public_transport / highway / building）の type と名前を
  `WaypointType.infer` に（natural/water の湖を「給水」にしないため、地名・自然物の type は使わない）。
- **画面**（`PlaceSearchState` と部品を 3 画面で共用）:
  - ルートプランの地図（全画面でも）: 地図の左上に検索欄（右のボタン列は避ける）。結果 → 地図がそこへ（広がりのある場所＝対角 1.5 km 超は範囲に合わせる、
    それ以外はズーム 16）・紫のピン・下にカード →［経由地として追加］= 種類を選ぶいつもの `WaypointDialog` を名前（と推定した種類）を入れて開く。
  - ルートを描く: 同じ検索欄（使い方の説明はその下）。結果 → 移動 →［ここに点を打つ］（終点の後に足す）。カードの分だけ地図の `contentPadding` を空け、ズームのボタンとロゴを隠さない。
  - 走行画面: 右のボタン列の虫眼鏡で検索欄を開く（普段は畳む。ヒントは「止まってから」）。結果を選ぶと追従を「しない」にして移動 →［ここへ向かう］（`Destination`、地点だけの目的地）/
    （ルートサイクリング）［経由地として登録して向かう］（既存の `addWaypoint(thenGo = true)`）。
  - 一覧は地図に重ねる（名前・住所の要約・現在地から、現在地が分からなければ「地図の中心から」の距離。検索したときの位置で測る）。0 件・失敗の文も同じ所に。
    戻るキーは一覧・選んだ場所 →（走行画面は）検索欄の順に閉じる。
  - **出典**: 一覧と選んだ場所のカードには必ず「場所検索: Nominatim / © OpenStreetMap contributors」（`NominatimSearch.ATTRIBUTION`。ODbL の帰属表示）。
    設定の「このアプリについて」にも。
- **保存しないもの**: 検索語・結果は端末に保存しない（画面を離れると検索欄も空に戻る）。選んで登録した経由地・点・目的地は利用者のプランなどの中身になる。
- テスト（`PlaceSearchTest`、通信なし。http・時計・待ち方を差し替える）: 応答の解析（name が空、位置の無い要素を飛ばす、配列でない）、住所の要約、種類の推定、
  URL（エンコード・パラメータ・viewbox の丸めと付けない場合）、User-Agent、1 秒の間隔（終わってから・失敗も数える）、キャッシュ（同じ語・前後の空白・0 件・丸めた範囲）、
  失敗の種類とキャッシュしないこと・オフラインでは送らない。

- **獲得標高**（`stats/ElevationGain`。純ロジック・単体テスト ElevationGainTest）: 0.8.0 までの数え方（GPS 高度の EMA α 0.3＋直近の底から 4 m）は drive_logger 0.7.0 と同じで、
  GPS の高度の雑音（σ 数 m）を登りとして何度も数えていた（合成データの平地 1 時間で 1200〜1430 m、ネットワーク位置が混ざると 10 分で 637 m。エミュレータの ±5 m の高度で 2 分 29 m）。
  drive_logger 0.8.0 と同じ計算に替えた: 使う点 = 高度あり・ネットワーク位置でない・高度の精度 ≤ 15 m（無い点は水平の精度 ≤ 20 m、精度も無い＝バックアップから戻した点は使う）。
  区間ごとに前後 2 点の中央値 → 前後 60 秒かつ走った距離で前後 300 m の移動平均 → 直近の底から **10 m** 以上上がったときだけ数える。
  **記録の詳細の獲得標高・区間の登り・全記録のまとめ・SNS 用の画像・一覧はすべてこの値**（`track.ascentM` に入れ直したもの。区間の登りは `ElevationGain.gainsOf` の時刻をその時点の走行距離の区間に入れ、
  合計 = 記録の獲得標高）。記録中の表示だけは後ろ向きの窓の `ElevationGain.Live`（同じ点・中央値・ヒステリシス、窓は直近 120 秒・600 m＝前後の窓と同じ幅）で、
  登りが 1 分ほど遅れて増え、終えると `of` の値に置き換わる（合成データの +60 m で 60.5 m / 60.5 m）。ルート（GPX）の獲得標高は DEM 由来の滑らかな値が多いので今までどおり `AscentCounter.forRoute`。
  - 合成データ（白色 σ 5 m＋ずれ σ 4 m・τ 60 s＋ときどき 30 m の跳び、1 Hz）: 平地 1 時間で 10〜20 m、100 m の坂で 100〜111 m、40 m の坂 6 回（真 240 m）で 172〜192 m

  - 限界: GPS の高度は水平より悪く、数分かけて 10 m 前後ずれる。平地でも 1 時間で 10〜20 m 程度は出ることがある（目安）。
- **比較表示**（記録の詳細の地図の左の［生の GPS の点を重ねる］（ScatterPlot。［マス］の上））: 赤紫の細い線＝記録した点。ズーム 16 以上で、見えている範囲の点（最大 400）と精度の円（accuracy の半径）。
  色の線（設定が ON ならなめらかにした線）と見比べられる。凡例は地図の左下（「生の GPS の点と精度の円（色の線は表示している軌跡）」、引いているときは「生の GPS の線（寄ると点と精度の円）」）。
  記録した点は 0.1.0 から全部残っているので、既存の記録でも表示できる（精度 30 m 超などで捨てた測位は無い）。

## 4.10 ファイルから記録を取り込む（0.10.0、`importer/`・`ui/TrackImportScreen.kt`・Room 版 5）

2026-10-16 ユーザー要望「GPX・FIT・KML が沢山入った zip を読んで、サイクリング記録データを作る機能を入れて。その場合、日付単位でサイクリングを分けて。」

- **入口**: 記録の一覧の右上のボタン（UploadFile。記録が無いときは画面の中にも）→ SAF（`OpenMultipleDocuments`、`*/*`。複数選べる）。
  zip・単体の .gpx / .fit / .tcx / .kml / .kmz / .gz。**他アプリからの「開く」「共有」で zip を受けるのは入れていない**（今の「開く」は GPX をプランに入れる流れなので、混ぜると分かりにくい）。
- **流れ**（`importer/ActivityImporter`。`CycleApp.activityImport`、アプリのスコープ＋IO で動くので**画面の回転・ほかの画面への移動では止まらない**。アプリを閉じる（プロセスが終わる）と止まる）:
  読む（`Reading`: 読んだバイト / 全体（SAF の SIZE）・ファイル数・点の数・今のファイル、［やめる］）→ 日ごとに分けて統計を出す（`Planning`）→
  確認（`Review`）→ 保存（`Importing`。1 日ずつトランザクション。やめてもそれまでの日は残る）→ 結果（`Done`）。画面を離れても、記録の一覧の上に帯（読み込み中 / 確認待ち n 日分 / 保存中）が出てそこから戻れる。
- **メモリ**: zip は `ZipInputStream` で頭から順に読むだけ（丸ごと載せない）。点は**一時ファイル**（`cache/activity_import/points.bin`、1 点 32 バイト: 時刻・緯度・経度・高度・速度。`FileSpool`）に書き、
  メモリには線の目録（`RunInfo`: ファイル番号・形式・種目・一時ファイルの位置・点数・始まり・終わり）だけ。日ごとの統計・保存は 1 日分ずつ一時ファイルから読んで作る（数百ファイル・数十万点でも 1 日分の点しか持たない）。
  一時ファイルは終わる・やめると消し、次の起動でも残っていれば消す。FIT と GPX は 1 ファイルをメモリに読んで解析する（1 ファイル展開後 64 MB まで。普通は数 MB）。
- **zip の中**（`ActivityReader`）: フォルダを問わず全部のエントリを見る。形式は拡張子（大文字小文字を問わない）。`.gz` は展開して中の名前で（Strava の `activities/*.gpx.gz`・`*.fit.gz`・`*.tcx.gz`）、
  入れ子の `.zip` / `.kmz` も読む（深さ 4 まで）。KMZ は中の .kml だけ。知らない拡張子（画像・CSV など）は「対象外」と数えるだけ、`__MACOSX/`・`._*` は数えない。
  SAF で選んだ単体のファイルで拡張子が分からなければ先頭のバイトで判定（PK / gzip / .FIT / `<gpx` / TrainingCenterDatabase / `<kml`）。1 ファイルは展開後 64 MB まで（超えたら「大きすぎます」、読めた点は使う）。
  エントリ名が UTF-8 でない zip（Windows の「送る → 圧縮」など）は `IllegalArgumentException` になるので、**MS932 で最初から読み直す**。XML の前の空白・BOM は飛ばす（Strava の TCX は `<?xml` の前に空白がある）。
- **形式**:
  - **GPX**（`GpxParser` を流用。trk の `type` を読むように足した）: trk/trkseg/trkpt の time・ele。trkseg ごとに線。**rte / wpt だけのファイル**は時刻が無いので記録にせず「ルート・経由地だけの GPX n」と出す。時刻の無い trk は「時刻なし」。
  - **FIT**（`FitParser`、自前。**Garmin FIT SDK は独自ライセンスなので使わない**）: ヘッダ 12 / 14 バイト・定義メッセージ（リトル / ビッグエンディアン）・データメッセージ・**圧縮タイムスタンプのヘッダ**（下 5 ビット、前より小さければ +32 秒）・
    **開発者フィールドは大きさだけ足して読み飛ばす**・連結された FIT。record（20）の timestamp(253)・position_lat/long（semicircles × 180 / 2^31）・enhanced_altitude(78) / altitude(2)（÷5 − 500）・enhanced_speed(73) / speed(6)（÷1000）。
    時刻は 1989-12-31T00:00:00Z からの秒。**位置の無い record（屋内・センサーだけ）は点にせず数だけ出す**。session(18) / sport(12) の sport（2 = 自転車）。
    **CRC（FIT の CRC-16）は確かめるが、合わなくても読めた点は使う**（「CRC 不一致」と出すだけ。電池切れなどで最後まで書かれていないファイルが実際にあるため）。途中で切れていれば読めたところまで（「一部だけ」）。
    心拍・ケイデンス・距離は使わない（保存する列が無い。距離は位置から測る）。
  - **TCX**（`TcxParser`）: Track ごとに線、Trackpoint の Time・Position・AltitudeMeters・拡張 TPX/Speed、Activity@Sport。位置の無い Trackpoint は数えるだけ。
  - **KML / KMZ**（`KmlParser`）: **gx:Track**（`when` と `gx:coord` の組。gx:MultiTrack の中も）は時刻つきの線。**LineString（時刻なし）**は、その Placemark か外側の Folder / Document に
    **TimeSpan（begin・end）があれば begin〜end を道のりに比例して割り振る**（一定の速さで走ったとみなす。道のりが 0 なら点の順に等間隔）。**TimeStamp だけ・何も無い LineString は取り込まない**
    （日付も走った時間も決められない。「時刻の無い線 n」と出す）。Point・Polygon は使わない。
- **種目**: GPX の trk/type・TCX の Sport・FIT の sport が**自転車以外（ラン・ウォーク・ハイクなど）と書かれたファイルは既定で外す**（確認画面のスイッチ「自転車以外…も入れる（n）」で入れて分け直す）。
  書いていない（分からない）ファイルは入れる。Strava の GPX の数字の type（1 = Ride、9 = Run、10 = Walk）は実物で未確認。
- **日付で分ける**（`DayPlanner`。純ロジック）:
  1. 線（`RunCollector`）: パーサの区切り（trkseg・gx:Track・TCX の Track）・ファイルの境目・**10 分以上の空き**で切る。2000 年より前・今より 1 日以上先の時刻、時刻が戻る・同じ時刻の点、(0, 0) は捨てる。2 点未満の線は使わない。
  2. **重複を除く**: 線を優先の順（形式 FIT > TCX > GPX > KML → 点の多い順 → 早い順）に見て、すでに採った時間帯（**前後 30 秒**の余裕。機器ごとの始まり・終わりの数秒の差）に入る点を捨てる。
     同じ走行が GPX と FIT の両方にあれば FIT だけ、一部だけ重なれば重ならない部分だけ残る（2 点未満なら捨てる）。
  3. **端末のタイムゾーンの日付**（点ごとのオフセット。夏時間も）が変わるところで切る。**0 時をまたぐ 1 本の走行は 2 日に分ける**（ユーザーの指示どおり）。
  4. 同じ日の片を時刻の順に並べて 1 日 = 1 記録。**片ごとに区間（segment）を分け、線をつながない**。
- **記録を作る**（`ImportBuilder`）: 点は記録中と同じ `RideTracker` に通し、受け付けた点だけを保存（100 km/h 超の跳び・同じ時刻は捨てる。跳びが続いて測り直したら区間を分ける）。
  色分けの速さ（`speed`）は記録中と同じ直近 3 回の中央値、`deviceSpeed` は FIT / TCX の速度、精度は null、provider = 4（取り込み）。
  **止まっていた時間の扱い**: 自動一時停止の考え方に合わせる。多くの機器は止まっている間（オートポーズ）記録しないので、点が **30 秒を超えてあき、その間に 3 km/h 未満しか動いていなければ区間を分ける**
  （そのまま流すと、動き出した最初の点の速さ（中央値）で止まっていた数分を走行時間に数えてしまう）。あいていても動いていれば（トンネル・間引いた記録）同じ区間で、時間と距離を数える。
  統計（距離・走行時間・最高・獲得標高）は記録を終えたときと同じ `TrackRepository.statsOf`（設定が ON ならなめらかにした点で距離。獲得標高は `ElevationGain`。取り込んだ点は精度が無いので「バックアップから戻した点」と同じく使う）。
  自動一時停止は今の設定のまま記録に入れる。名前は「2026-05-03 取り込み」、mode は free（フリー）、`importFormat` = その日に使った形式（"fit,gpx"）。開始 = その日の最初の点、終了 = 最後の点。
- **既存の記録との重複**（`ImportBuilder.overlapping`）: 終わっていない記録も含むすべての記録の［開始, 終了（無ければ今）］と、その日の片の時間帯が重なれば「重複の可能性: 記録名」を赤で出し、**既定は選ばない**。
  ［重複以外を選ぶ］［すべて選ぶ］［選択を外す］、行のタップで選ぶ / 外す。同じ zip をもう一度取り込むと前に取り込んだ日が全部「重複の可能性」になる。**（0.10.1 で変更: 活動単位の重複・既定ですべて選ぶ。§4.10.1）**
- **確認画面**: 「n 日分の記録が作れます（選んだのは m 日）」・選んだファイル名・読んだファイル数と点の数・ルート / 経由地だけの GPX・対象外の数・自転車以外のスイッチ、
  「読めなかった・一部だけのファイル n」（開くとパスと理由: 一部だけ / ルート・経由地だけ / 時刻なし / 位置なし / 読めません / 大きすぎます、補足（CRC 不一致・位置の無い点 n・TimeSpan から時刻を割り振った線 n など）。200 件まで）、
  日ごとの行（日付と曜日・距離・走行時間・最初〜最後の時刻・元のファイル数と形式・重複の印・自転車以外を含む印、▼でファイルの一覧）、下に［やめる］［取り込む（m 日）］。
  重複で全部捨てたファイル（9/20 の GPX など）は日の行の「元のファイル」に数えない。
- **取り込んだ記録**: 一覧・詳細の 2 行目が「取り込み（FIT・GPX）」。統計・区間・速度の分布・なめらかさ・まとめ・開拓したマス・SNS 用の画像・GPX の書き出し・ルートとして保存・写真の追加は自分の記録と同じ。
  記録の詳細の［生の GPS の点を重ねる］は「取り込んだ元の点を重ねる」（凡例「取り込んだ元の点（精度の情報は無い）」。精度の円は出ない）。
  **全体時間・まとめの「いちばん長い時間」は最初〜最後の点の経過時間**なので、朝と夕方の 2 回を 1 日にまとめた日は間の時間も入る（走行時間には入らない）。
- **権限・通信は増えていない**（SAF で選んだファイルを読むだけ。プライバシーポリシーには取り込んだ記録を端末の中に保存することを 1 行足した）。
- テスト（`ActivityImportTest`）: FIT（圧縮タイムスタンプ・ビッグエンディアンの定義・開発者フィールド・位置の無い record・sport・CRC 不一致・途中で切れた・FIT でない）、
  zip の再帰（フォルダ・入れ子の zip・.gpx.gz / .FIT.GZ / .tcx.gz・ルートだけ・時刻なし・壊れた FIT・対象外・__MACOSX）、TCX（前の空白・速度・高度・位置の無い点・種目）、
  KML（gx:Track・TimeSpan の道のり比例・TimeStamp だけの線・KMZ）、種目での除外、0 時での分割（東京・UTC）、10 分の空き、GPX と FIT の重複と一部の重なり、止まっていた空きと動いていた空き、既存の記録との重複、一時ファイルの往復。

  1. **取り込み済み**: 取り込みの印（`ActivityKeys`: ファイルの中身（展開後）の SHA-256 の先頭 16 バイト・FIT の file_id（製造元/シリアル/作成時刻）・Strava の Activity ID、それぞれ ＋ 活動の始まりの秒）を

     200 m より遠い → 別の場所（両方残す・印）。それ以外・重なりが少し → 重なる時間（既存の記録の続いた時間、前後 30 秒）の点だけ捨てる。

### 4.11.1 場所の判定

- **範囲**（`PlaceArea`）: 円は中心を原点にした局所平面（中心の緯度で経度を測る正距円筒）で、**線分と中心の距離 ≤ 半径**（頂点が円の中に無くても線分が横切れば通った）。
  矩形は緯度経度のまま Liang–Barsky で線分を切り取れるか。半径は 50 m〜200 km に丸める。南北が逆の矩形は何にも当たらない。日付変更線をまたぐ範囲は扱わない（見えている範囲がまたぐときは条件にしない）。
- **通った** = 記録の索引の線（区間ごと。**区間の間はつながない**）のどれかの線分が範囲にかかる。まず記録の外接矩形と範囲の外接矩形、次に線分ごとの外接矩形で外す。
  **出発 / 終了** = 記録の最初 / 最後の点が範囲に入る。
- 線は記録した点（測位そのもの。なめらかにした点ではない＝設定で変わらない）を区間ごとに **Douglas–Peucker 10 m** で間引いたものなので、境目の ±10 m ほどはどちらにもなりうる
  （単体テストで、ランダムな走行 150 本 × 円 20 個を全点の総当たりと比べ、食い違うのは境目の ±15 m の中だけ）。

## 4.4 ルートを描く（0.3.0、`draw/`・`ui/RouteDrawScreen.kt`）

- 入口: プラン編集の地図の右の［ルートを描く］（手書きの線のアイコン）とメニュー、ルートの ︙ の［描いて編集］。
- 操作: 地図をタップで終点の後に点を足す（直線でつながる）。線の近く（画面で 20 dp 以内）をタップすると、その区間の最も近い t で
  **de Casteljau 法で分割**して点を入れる（曲線でも形は変わらない）。点は長押しでドラッグ移動。点を選ぶ（オレンジ）とハンドル（青）が出て、
  ドラッグで前後の区間が 3 次ベジエになる。選んだ点をもう一度タップで「角 ⇔ なめらか」。下のボタン: 点を削除・角 / なめらか / 対称・ハンドルを消す・
  全体をなめらかに（Catmull-Rom 相当: 中の点のハンドル = (次 − 前) / 6）・折り返し（来た道を逆順に足す）・始点に戻る。上に元に戻す / やり直し（200 回）。
  距離は合計と、選んだ点の前後の区間。［終わり］で名前と色を決めて保存。保存せずに戻るときは確認。
- 点の種類: 角 = ハンドル独立（無ければ直線）、なめらか = 前後のハンドルが一直線（長さは別）、対称 = 一直線かつ同じ長さ。
  なめらか / 対称にしたときハンドルが無ければ自動で付ける。
- 計算は局所平面（`Enu`: 最初の点を原点にした東・北の m）で行い、緯度経度に戻す。表示・距離・GPX 用の点は、曲線を区間の長さ / 100（2〜5 m）の
  道のりでほぼ等間隔にサンプリング（直線は 2 点）。
- 保存: `route.editShape` に `DrawnShape`（アンカーの緯度経度・ハンドル（m）・種類、区間ごとの引き方）の JSON、`route_point` にはサンプリングした点
  （標高なし。GPX 書き出し・案内・距離はこの点を使う）。描いたルートは何度でも曲線のまま編集し直せる。バックアップの manifest にも editShape を入れる。
- GPX のルートを［描いて編集］すると、形を保ったまま Douglas–Peucker で 300 点以下（許容誤差 3 m から倍にしていく）の角の点に変換して編集する
  （区間の切れ目はつながり、標高は消える。保存するまで元は変わらない、と確認を出す）。
- **道に沿う方式を足すときの入口**: 2 点間の線は `SegmentRouter`（`draw/Bezier.kt`）が作る。今は `StraightRouter`（ハンドルが無ければ直線、
  あればベジエ）だけ。道に沿う方式は `SegmentRouter` を実装して `Routers` に登録し、`DrawnShape.methods`（区間ごとの id。足りなければ straight）に
  その id を入れる。route_point と GPX は引いた結果の点なので、Room の列や書き出しは変えずに足せる。UI の切り替えはまだ出していない。
- テスト（`RouteDrawTest`）: 追加・挿入・削除・元に戻す / やり直し・ドラッグは 1 回分の履歴、de Casteljau の分割が完全に一致・分割しても形と長さが変わらない、
  なめらか / 対称 / 角の制約、サンプリングの長さの誤差 0.1% 未満・間隔 5.5 m 以下、折り返し・閉じる、最も近い区間と t、JSON の往復と再編集、GPX の往復、GPX の点からの変換。

### 6.1 バックアップと記録の取り込みの取り違え（0.10.2、2026-10-17、`importer/FileKind.kt`）

利用者が Strava の書き出しの zip を設定の［バックアップを読み込む］で選び、エラーになった（正しくは記録の一覧の右上の［ファイルから記録を取り込む］）。

- **判定**（`FileKind.classify`。純ロジック）: 先頭から軽く覗くだけ。zip はエントリを頭から順に見て、決まったところでやめる（全部は読まない）。
  最上位の `manifest.json` → バックアップ。`plans/plan_N.gpx`・`tracks/track_N.gpx`（バックアップの GPX）は決め手にせず先を見る（manifest はバックアップの最後に入っている）。
  それ以外の GPX / FIT / TCX / KML / KMZ / .gz（`.fit.gz` など）・`activities.csv`・入れ子の zip の中のそれら → 記録のファイル。
  最後まで manifest が無くバックアップの名前の GPX だけ → 記録のファイル（GPX として読める）。何も無い → どちらでもない。3000 エントリ / 48 MB 見ても決まらない → 決まらない。
  単体のファイルは拡張子（.gpx / .fit / .tcx / .kml / .kmz / .gz）、無ければ先頭のバイト（gzip・FIT・`<gpx`・TrainingCenterDatabase・`<kml`）。
- **設定の［バックアップを読み込む］**（`MainViewModel.importBackup`）: 記録のファイル → ダイアログ「このファイルはこのアプリのバックアップではありません。走行の記録（GPX・FIT など）が入っているので、
  ［ファイルから記録を取り込む］で読めます」［取り込みへ進む］［キャンセル］。［取り込みへ進む］は**同じ URI のまま** `ActivityImporter.start` を始め、記録の一覧 → 取り込みの画面へ
  （戻ると記録の一覧なので入口が分かる）。どちらでもない → ダイアログで何が読めるか（このアプリの書き出しの ZIP / GPX・FIT など は記録の取り込みから）。
  バックアップ・決まらない → 今までどおり一時ファイルにコピーして読み込む。manifest が無くて失敗したら、コピーした一時ファイルを最後まで見て案内を出す。判定・読み込みの間はボタンを止める。
  説明文に「Strava などの記録（GPX・FIT・書き出しの zip）は、記録の一覧の右上の［ファイルから記録を取り込む］から読めます。」を足した。
- **逆方向**（記録の取り込みでバックアップの zip を選んだ。1 ファイルのときだけ）: `ActivityImporter.State.LooksLikeBackup` の画面
  ［バックアップとして読み込む］（同じ URI で判定を飛ばして `importBackup`）［記録の取り込みとして続ける］［キャンセル］。
- **SAF の権限**: `OpenDocument` / `OpenMultipleDocuments` で受けた URI の読み取り権限は、受けたアクティビティ（このアプリは 1 つだけ）が続く間は有効なので、
  ダイアログで待ってから同じ URI を読んでも読める（エミュレータで 20 秒待ってから［取り込みへ進む］で確認。永続化（takePersistableUriPermission）はしていない。
  プロセスが終わると案内も消えるので問題ない）。
- テスト（`FileKindTest`）: バックアップの zip（manifest が最後・manifest だけ）・Strava 風の zip（最初のエントリで決まり後ろは読まない・activities.csv・入れ子の zip・
  バックアップの名前の GPX だけ・下のフォルダの manifest）・単体の GPX / FIT / TCX / KML / KMZ / .gz と拡張子なしの中身・関係ないファイル（画像・テキスト・空・対象外だけの zip・壊れた zip）・上限で決まらない。
- エミュレータでの確認（2026-10-17、emulator-5554、0.10.1 → 0.10.2 の上書き）: 合成の Strava 風 zip（5 本）を［バックアップを読み込む］→ ダイアログ → 20 秒後に［取り込みへ進む］→ 確認画面（4 日分）。
  単体の GPX → 同じダイアログ。テキスト → 読めないファイルのダイアログ。取り込みでこのアプリのバックアップ zip → 「このアプリのバックアップです」→［バックアップとして読み込む］で記録が 1 件増える。

## 10. 更新の確認（0.4.0、`update/`・`ui/UpdateUi.kt`）

ユーザー指示（2026-10-12）「最新版の更新確認機能も入れてください。phonetic hound と同様にしてください。」→ Phonetic Hound の DESIGN.md §13.7
（`core/.../update/UpdateCheck.kt`）と同じ仕組み・同じ挙動。配布は GitHub（android-apps の Releases）で自動更新が無いので、新しい版が出たらアプリの中で知らせる。
Google Play では配っていないので、Play の「Play 以外での更新・更新版への誘導の禁止」は当たらない（Play で配ることになったら link_conne2 と同じく flavor で外す）。

- **読む先**: `https://raw.githubusercontent.com/kijitora-no-hito/android-apps/main/releases.json`（全アプリのリリース一覧。公開の手順 `MAINTAINING.md` で
  版を上げるたびに更新される）。`folder == "cycle_route_logger"` のエントリの `tag`（`cycleroutelogger-v0.4.0`）と `notes` だけを使う（`apk` は公開する人の PC のパスなので
  使わない）。同じフォルダが複数あれば一番新しい版。タグは英数と `._-` だけのものを読む（URL にそのまま入れるため）。JSON は kotlinx-serialization の `parseToJsonElement`。
- **版の比較**（`AppVersion`）: タグの `v` の後ろと、いまの `versionName` を数の組で比べる（`0.9` < `0.10`、足りない桁は 0）。同じ数なら正式版が新しい（`0.4.0-dev` < `0.4.0`）。
  新しいときだけ知らせる（同じ・古いは何も出さない）。軽量版の区別は無い（Phonetic Hound の `-lite` の扱いは外した）。
- **いつ**: 起動して最初にホームが出たとき 1 回（プロセスごと）、IO スレッドで（GET 1 回・接続と読み取りのタイムアウト各 8 秒・1 MB まで。`RemoteContent.readCapped` を共用）。
  前回の**試行**から 6 時間以内なら省く（失敗しても試行の時刻は進める）。失敗・形の違う応答は黙って無視（帯を出さないだけ）。設定の［今すぐ確認］は間隔を見ない。
  最後に読めた版（タグと notes）と時刻を SharedPreferences `update`（設定の `settings` とは別）に覚え、起動のたびにいまの版と比べ直す
  （6 時間以内の起動・オフラインでも帯が出る。更新した後に古い「新しい版」が残らない）。
- **設定 OFF のときは一切通信しない**（`Settings.updateCheck`、キー `update_check`、既定 ON。起動時の確認をせず、［今すぐ確認］も押せない、覚えている版があっても帯を出さない）。
- **送るもの**: HTTPS の GET 1 回だけ（ヘッダは HttpURLConnection の既定のまま。User-Agent も変えない。GPX の URL 取り込みの `RemoteGpxFetcher` とは別）。
  記録・プラン・位置・端末の識別子は送らない。
- **知らせ方（アプリ内だけ。Android の通知は使わない）**: ホームの上部に控えめな帯「新しい版 v0.x.y があります」［更新内容］［ダウンロード］［あとで］。
  **記録中は出さない**（走行画面には元から無く、ホームでも記録中の間は隠す）。
  - ［ダウンロード］= ブラウザ（ACTION_VIEW）で `https://github.com/kijitora-no-hito/android-apps/releases/download/<tag>/cycleroutelogger-<版>-release.apk`。
    アプリは APK を落とさない・インストールしない（`REQUEST_INSTALL_PACKAGES` は要求しない）。
  - ［更新内容］= ダイアログ: notes の箇条書き（`- ` の行、`**` を外して先頭 6 行）・入れ方（上書きインストールで記録とプランは残る・「提供元不明のアプリ」の許可）・
    ［あとで］と OFF の説明。ボタンは［ダウンロード］［説明ページ］［閉じる］。
  - ［あとで］= その版は次に起動するまで出さない（メモリだけ）。さらに新しい版が出たら出す。［今すぐ確認］を押すと取り消す。
- **設定**: 「更新」の節に「更新の確認」ON/OFF（説明つき）、状態の 1 行（確認中… / 最新の版です（M/d HH:mm に確認）/ 新しい版 v… があります（ホームから）/
  確認できませんでした（最後に確認できたのは …）/ 最後の確認: … / まだ確認していません / 確認しません（通信しません））、［今すぐ確認］［説明ページを開く］。
  「このアプリについて」にも通信の 1 文。
- **debug だけ「古い版のふり」**: `adb -s emulator-5554 shell am start -n jp.kjtr.cycleroutelogger/.MainActivity --es updateAs 0.2.0`
  = いまの版を 0.2.0 として比べ直し、すぐ取りに行く（設定 OFF なら取りに行かない）。プロセスが続く間だけ。ログは `CRL-Update`。
- **限界**: 0.3.0 以前にはこの機能が無いので、0.4.0 への更新だけは今までどおり（説明ページ・Releases）で知らせる。releases.json の形・置き場が変わると
  読めなくなる（黙って「確認できませんでした」）。
